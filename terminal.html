Get Weald

Feature

The terminal

Weald hosts real login shells inside its own window, one set per project. These are genuine terminals: git, vim, claude, and anything else behave exactly as they would elsewhere.

The engine

macOS provides no supported way to place another application's window inside your own, so Weald does not attempt to embed an existing terminal application. It implements a terminal emulator, which is what native Mac applications do in this situation. The emulator forks a login shell over a pseudo-terminal and is compatible with xterm-256color.

The first-party engine is built in layers: a pseudo-terminal and process supervisor, an incremental UTF-8 decoder and ANSI parser, a screen buffer with reflow and selection, and a renderer. Rendering defaults to Metal, drawing instanced quads against a glyph atlas that rasterizes each glyph once per style and scale, with color emoji passed through. A Core Text renderer is available as a fallback.

Tabs and split panes

Each project has its own tabbed terminal. New tabs are numbered monotonically, so titles remain stable as others are closed. A tab can be split into as many as four side-by-side panes; a split is inserted immediately to the right of the focused pane and takes the caret. Closing peels one pane at a time and only closes the tab once a single pane remains.

Every pane runs its own login shell in the project directory. Font size changes apply to all panes at once. A tab that has not been split renders with no pane chrome at all.

Session persistence

Terminal sessions are owned by a process-wide registry keyed by project, not by the view that displays them. Switching to another tab in the project view, or to another project entirely, does not destroy the shells. Returning restores the same sessions with their scrollback intact.

The same registry allows a command to be delivered to a project whose terminal has never been opened: the command is queued against a new tab and flushed into the shell the moment it is created.

Tab grouping and color

Tabs color themselves according to the kind of work the session is doing, so the tab bar communicates the state of several sessions at a glance. Classification reads the text of the task delivered to the tab and the title the running session reports as it works.

Classification runs first as an instant offline keyword match. Where a local Claude Code login is available, a short headless call refines the result, memoized by input and falling back to the keyword result on any failure. The entire feature can be disabled, individual groups can be turned off or recolored, and any tab's color can be pinned by hand.

Sending work to Claude

Every path in the application that starts a Claude session goes through one function. It selects the target project, switches to its terminal, opens a fresh tab, and types a cd into the project directory followed by the claude invocation. The consequence is that a session started from the tray, from the board, or from a suggestion card is the same kind of session, visible in the same place, with no hidden background process.

A separate mechanism, Quick Send, hands a session off to an external terminal application when that is preferred.

The console

Weald's default launch surface is a first-party console. Each line entered is routed by a simple, deterministic classifier: an explicit prefix forces shell or chat mode, a leading slash invokes a Weald command, a leading exclamation mark passes through to the shell, and a line whose first word resolves on PATH and reads as a command is executed. Anything else is treated as a message to the language model. The effect is that git status runs as a command while git is great. is understood as a sentence.

The console shares the application's ticket store and model client, so it and any connected agent operate on the same state. It can be dismissed to reveal the full mission-control interface, and reopened from the sidebar or with a shortcut.

Minimal mode

Minimal mode collapses the application to the selected project's terminal tabs beneath a slim bar holding a project switcher, a model-readiness indicator, and an expand control. It is intended for use as a compact, always-present console. The project chosen in minimal mode is the project selected when the full interface is restored.

The context map

Weald mines Claude Code transcripts for each project into a local co-occurrence graph of files, prompt terms, and commands. No model inference is involved and nothing is transmitted. Pairs of items appearing in the same conversational turn strengthen an edge between them, and edge weight halves roughly every two weeks so that stale context recedes.

The graph is used in two ways at once. As a map, it renders the project's live context as a field that responds to what you are typing. As autocomplete, matching entries surface as suggestion pills that inject a file mention, a completed word, or an entire past prompt directly into the terminal.
