Weald in brief

Weald is a native macOS application that combines a terminal with a mission-control view of agent-driven development. It observes the repositories you work in, the Claude Code sessions running against them, their git history, and a plain-file ticket system, and presents all of it on one surface.

What the application does

Most of the work in an agent-assisted project happens in a terminal, and the record of that work is scattered across shell sessions, commit history, and whatever notes were kept along the way. Weald consolidates those sources. It hosts the terminal sessions itself, so it can observe them; it reads git and Claude Code session data directly from disk, so it requires no instrumentation of your projects; and it stores task state as ordinary files inside each repository, so that state is versioned alongside the code it describes.

Four capabilities follow from that arrangement.

  • An embedded terminal. Real login shells with tabs, split panes, and a first-party terminal engine, running inside the application window per project.
  • Overwatch. A full-screen view of every live session for a project, each one still interactive.
  • A file-based ticket system. Tasks are .wealdticket files committed to the repository, readable and writable by people and by agents.
  • An MCP server. Agents report status, raise questions, and update tickets through a local endpoint.

Design principles

Files are the source of truth. Ticket and project state live in a visible, git-tracked .weald/ directory in each repository. There is no database and no hosted backend. State survives a clone to another machine, ticket history is git history, and any tool that can read a file can read a Weald ticket.

Agents do not depend on the application being open. When Weald is running, agent writes arrive over MCP and update the interface immediately. When it is not running, the same writes land as file changes, and Weald replays them at next launch.

Inference is separated from record. Work an agent performs at your instruction is recorded without a gate. Suggestions produced by a language model are staged as drafts and are never written to disk until you approve them. Every ticket carries an origin field recording which of the two it was.

Nothing leaves the machine unless you configure it to. Project scanning, git reading, session observation, the terminal, and the context map are entirely local. Network access occurs only for license verification, the update check, and any language-model features you enable with your own key.
