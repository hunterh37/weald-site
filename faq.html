Questions and answers

Direct answers to the questions asked most often about what Weald is, what it requires, and what it does with your data.

General

What is Weald?

A native macOS application that combines a terminal with a mission-control view of agent-driven development. It hosts your shell sessions, reads git history and Claude Code session data, and keeps task state as plain files inside each repository.

Is it a terminal or a project manager?

Both, and the combination is the point. Because Weald hosts the terminal sessions itself, it can relate what an agent is doing right now to the commits it produced and the tickets it is working against. A separate terminal and a separate task tracker cannot make that connection.

Does it replace GitHub Issues or Jira?

No. Weald's tickets are a developer-facing and agent-facing record that lives in the repository. GitHub data is read in where it is available, and a suggestion can be promoted into a GitHub issue, but Weald is not intended as the tracker external stakeholders use.

Does Weald run my agents for me?

It starts Claude sessions on request and observes them, but it does not autonomously drive them. Weald is the surface above your agents rather than an orchestrator of them.

Do I have to use Claude Code?

No. The terminal, the ticket system, git history, and the team view work with any tool. Session observation, the context map, and the usage gauge are the parts that depend on Claude Code being present, and they are inactive without it.

Installation and licensing

What does it require?

macOS 14 or later. The gh CLI is optional and adds GitHub data. An OpenRouter key is optional and enables the language-model features.

How is it licensed?

A one-time purchase with a license key. There is no subscription and no account to create. The key is verified against Gumroad's public endpoint, and Weald operates no server of its own for this purpose.

Does it work offline?

Yes. License verification is offline-tolerant, so an activated copy continues to run without a network connection. Everything except the language-model features, GitHub enrichment, and the update check is local in any case.

Can I use it on more than one Mac?

Activations are counted against the license. Activating on an additional machine consumes one; ordinary relaunches do not.

How do updates work?

Weald checks a small public manifest at launch and shows a dismissable banner when a newer version exists. Nothing is installed automatically, and the check fails silently when offline.

Data and privacy

Does my code leave my machine?

Not unless you enable a language-model feature and supply your own key. Project scanning, git reading, session observation, the terminal, the context map, and the team view are entirely local. Weald has no backend that receives your project data.

What is sent when I do enable model features?

Only the context assembled for the request in question: recent commits, open ticket titles, activity, and an excerpt of project documents, trimmed to a budget. Requests go to OpenRouter using your key. Where the system supports on-device inference, that engine is preferred and nothing is sent at all.

Where is my API key stored?

In the system Keychain, and nowhere else. It is never written to a project file or to application preferences.

Does Weald modify my Claude Code data?

No. Session files under ~/.claude/ are read only. Installing Weald changes nothing about how Claude Code behaves.

What does the companion application transmit?

An encrypted, read-only snapshot on the local network, containing usage windows, git and team rollups, and the attention queue. Terminal output, file contents, diffs, prompts, and transcript text are excluded by design, and the companion cannot run anything on the Mac.

Tickets and agents

Where are tickets stored?

In a visible .weald/ directory inside each repository, as Markdown files with a YAML header. They are committed with your code, so they survive a clone and their history is your git history.

Can I edit a ticket by hand?

Yes. The format is ordinary text and is designed to round-trip safely, so a file edited in your own editor and a file written by an agent are the same kind of file.

Will an AI create tickets without my approval?

No. A model proposal is written to an ignored proposals directory and rendered as a draft. It becomes a real ticket only when you accept it, and the resulting ticket records that its origin was a proposal. Work an agent performs at your instruction is recorded without a gate, because you asked for it.

Do agents need Weald to be running?

No. With the application open, changes arrive over the local MCP endpoint and update the interface immediately. With it closed, the same changes land as file writes and are replayed at next launch.

What if two agents edit the same ticket?

Writes are atomic, performed as a temporary file followed by a rename, so a partial ticket is never observed. A writer checks the modification timestamp before overwriting to detect a conflict, and git history remains the final backstop.

Is the MCP endpoint exposed to the network?

No. It binds to the loopback interface only and is unreachable from outside the machine.

Terminal

Is it a real terminal?

Yes. Each pane runs a genuine login shell over a pseudo-terminal, compatible with xterm-256color. Interactive programs behave as they do in any other terminal.

Can I use my existing terminal instead?

Yes. Quick Send hands a session off to your preferred external terminal application. The embedded terminal exists for staying inside Weald, not for replacing what you already use.

Do sessions survive switching views?

Yes. Sessions are owned by a process-wide registry keyed by project rather than by the view showing them, so moving between tabs and projects leaves shells and scrollback intact.

Will Weald intercept my keystrokes?

Only the shortcuts in the reference table. Everything else reaches the shell untouched, so editors and interactive tools are unaffected.

Does it change my shell configuration?

Only if you ask it to. When you do, the original file is backed up first and every line Weald writes is confined to a delimited managed block that can be removed cleanly.
