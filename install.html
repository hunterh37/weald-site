Get Weald

Getting started

Install and first launch

Weald is distributed as a signed and notarized disk image. Installation is a copy into the Applications folder, followed by license activation and a short setup walkthrough.

Download

Download the disk image directly, or retrieve it from the command line.

curl -LO https://hunterh37.github.io/weald-site/Weald-0.4.dmg

Open the image and drag Weald into /Applications. Because the build is notarized, no security override is required on first open.

License activation

Weald is a one-time purchase. On first launch the application presents an activation panel and remains blocked until a valid key is entered. The key is issued at purchase and verified against Gumroad's public license endpoint; there is no account to create and no server operated by Weald.

Later launches re-verify the key without incrementing the activation count. Verification is offline-tolerant: if the machine has no network connection, a previously activated copy continues to run.

First-run walkthrough

After activation, a short and fully skippable walkthrough runs once. It covers three steps: a one-line introduction, an accent-color picker that recolors the interface as you choose, and a live terminal in which the keyboard shortcuts can be tried immediately. An optional final step offers to configure a modern zsh environment.

The walkthrough can be replayed at any time from Settings, Getting started, Replay intro.

Optional shell setup

The shell step writes a curated configuration into ~/.zshrc using well-established open-source tools, among them Starship, zsh-autosuggestions, zsh-syntax-highlighting, zoxide, and fzf. Two safeguards apply without exception: the original file is backed up before any write, and everything Weald writes is confined to a clearly delimited managed block that can be removed later without disturbing your own configuration. The same editor is available afterwards in Settings, with a live preview of the file that will be produced.

Adding projects

Weald finds work in three ways. It scans the root folders you configure for directories containing a .weald/ folder, or a .git directory accompanied by a project document. Folders can also be dragged into the application directly. Nested repositories inside a scanned root are discovered as separate projects. The resulting list is persisted between launches.

Once a project is present, Weald reads its git history by polling git log and watching .git/logs/HEAD. No hook installation is required. An optional post-commit hook is offered for instantaneous updates, but the application is designed to work fully without it.

Claude Code sessions

If Claude Code is installed, Weald reads its session data from ~/.claude/ to determine which projects have an active or recent session, when each was last active, and how many tokens have been consumed. This is a read of files already written by Claude Code. Weald does not modify them, and installing Weald changes nothing about how Claude Code runs.

Updates

On launch, Weald fetches a small public manifest and compares its version to the running build. If a newer release exists, a dismissable banner appears with a download link. There is no automatic installer and no background updater; the check fails silently when offline.

Everything above except license verification and the update check runs locally. Adding a project does not upload it, index it remotely, or send any part of it anywhere.
